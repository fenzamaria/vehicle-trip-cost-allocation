# API Interface Documentation

Base URL (local): `http://localhost:8000`
Interactive explorer: `http://localhost:8000/docs` (auto-generated by FastAPI)

All endpoints operate against the **latest allocation run** by default (the most
recently created `AllocationRun`, by `run_at` timestamp).

---

## `POST /allocations/run`

Triggers a fresh, complete allocation run over all current source data in the
database. Creates a new `AllocationRun` with a new `run_id`, and a full new set
of `Allocation` rows — never mutates or appends to a previous run (see DESIGN.md
Section 4, "Re-runnability").

**Request body:** none

**Response `200 OK`:**
```json
{
  "run_id": "a5786c78-ad10-4ea9-966a-fd6bd99d18ee",
  "status": "completed"
}
```

---

## `GET /costs/trip/{trip_id}`

Returns the total cost attributed to a specific trip. **Only includes TRIP-level
allocations** — deliberately excludes VEHICLE-level costs, even for the same
vehicle (see DESIGN.md Section 2 — a trip's cost is only what's confidently tied
to *that specific trip*, not everything the vehicle incurred).

**Path parameter:**
| Name | Type | Description |
|---|---|---|
| `trip_id` | string | The trip's identifier, e.g. `T1` |

**Response `200 OK`:**
```json
{
  "trip_id": "T1",
  "run_id": "a5786c78-ad10-4ea9-966a-fd6bd99d18ee",
  "total_cost": 240.00
}
```
A trip with no TRIP-level allocations returns `"total_cost": 0` (not an error —
zero attributed cost is a valid, meaningful result, not a failure state).

---

## `GET /costs/vehicle/{vehicle_id}`

Returns the total cost attributed to a specific vehicle. **Includes both
TRIP-level and VEHICLE-level allocations** for that vehicle — a vehicle's total
can legitimately exceed the sum of its trips' individual costs, by design (see
DESIGN.md Section 2).

**Path parameter:**
| Name | Type | Description |
|---|---|---|
| `vehicle_id` | string | The vehicle's identifier, e.g. `V1` |

**Response `200 OK`:**
```json
{
  "vehicle_id": "V1",
  "run_id": "a5786c78-ad10-4ea9-966a-fd6bd99d18ee",
  "total_cost": 5575.00
}
```

---

## `GET /unattributed`

Returns every record from the latest run that could not be confidently
attributed even to a known vehicle, with its reason code (see DESIGN.md Section 5
for the taxonomy).

**Request body:** none

**Response `200 OK`:**
```json
[
  {
    "source_type": "TOLL",
    "source_id": "TL4",
    "amount": 50.00,
    "reason_code": "UNKNOWN_VEHICLE"
  },
  {
    "source_type": "DRIVER_EXPENSE",
    "source_id": "DE3",
    "amount": 120.00,
    "reason_code": "UNMAPPED_DRIVER"
  }
]
```
Returns an empty array `[]` if nothing is unattributed for the latest run — not
an error.

---

## `GET /reconciliation`

Returns a direct, queryable breakdown proving the conservation invariant for the
latest run: attributed total + unattributed total = grand total, which must equal
total recorded spend across the three cost-bearing sources.

**Request body:** none

**Response `200 OK`:**
```json
{
  "run_id": "a5786c78-ad10-4ea9-966a-fd6bd99d18ee",
  "attributed_total": 7675.00,
  "unattributed_total": 170.00,
  "grand_total": 7845.00
}
```

---

## Error Responses

| Status | When |
|---|---|
| `404 Not Found` | (Not currently distinguished from a valid zero-cost result — see Future Improvements: trip/vehicle IDs that don't exist at all currently return `total_cost: 0` rather than a 404, since the query doesn't check existence separately from summing. Flagged as a known simplification.) |
| `500 Internal Server Error` | Unexpected server-side failure (e.g., database connectivity issue) |

## Data Types

All monetary fields (`amount`, `total_cost`, `attributed_total`,
`unattributed_total`, `grand_total`) are serialized as JSON numbers but are
stored internally as `Decimal` (see Architecture.md Section 2 — never `float`,
to avoid rounding errors in financial data).
